# Lire et rejouer les preuves

- `couverture-ecrans.csv` consigne les rendus et ouvertures d’onglet, à partir d’une matrice fictive provenant du banc de recette 342 puis complétée avec les routes et les liens de la révision examinée. La colonne des captures est relative à la galerie locale. Le contenu d’un écran ne valide pas tous ses boutons.
- `routes-source.csv` donne le statut de rendu par type de page. `/espace/[orgId]` et `/agence/[orgId]` partagent une partie du code source. Les redirections, les écrans dont l’entrée normale est un lien de confirmation, et les variantes avec données manquantes demandent une preuve de parcours distincte. Le rôle `admin` correspond à une agence, `superadmin` à la direction.
- Les fichiers `tests-*` reprennent les tests métier inchangés du dépôt. Les projets du banc couvrent 390 × 844 et 1440 × 1000. Certaines suites fixent elles-mêmes les trois largeurs dans leur scénario. Le fichier de configuration d’audit est conservé en texte.
- `interactions.jsonl` contient les relevés initiaux des mouvements, dont les détours d’outillage. Le premier sélecteur d’agenda supposait une autre grille. Le premier rejeu des écrans de supervision est arrivé après expiration de la session fictive. Une fois la session renouvelée et le contrôle d’ouverture stabilisé, les résultats à retenir sont dans `interactions-complement.jsonl`, `interactions-afficher-details-navigation-supervision.jsonl` et `interactions-afficher-details.jsonl`. Pour le dernier cas, c’est le dernier fichier qui tranche. Une petite différence de délai d’ouverture sur le banc ne prouve pas un écart de performance en production.
- Les scripts ne sont prévus que pour `app/` dans un clone local du SHA audité, avec le banc PostgreSQL/Next de recette, les six sessions fictives existantes et une boîte e-mail fictive. Rejouer le compte avec le setup `e2e/auth.setup.ts` si la session est expirée. `E2E_BASE_URL` doit viser la boucle locale. Le balayage attend également une base PostgreSQL locale `SUPALOCAL_DB` et une matrice de parcours fictifs. La CLI Playwright du dépôt et le serveur compilé ne nécessitent aucune écriture en production.

Pour reproduire les tailles, lancer `node …/passer-les-ecrans.cjs <matrice fictive> <dossier local>` depuis `app/`. Un argument supplémentaire limite le passage à un rôle. Lancer `node …/observer-les-interactions.cjs <dossier local>` pour les gestes clavier et la préférence de mouvement. Le fichier `verifier-details-ux.cjs` relève le bouton d’inscription, le filtre SCI, l’arrivée au rendez-vous et les écrans de l’agence. Les sorties ne contiennent ni lien de confirmation ni état de connexion.
